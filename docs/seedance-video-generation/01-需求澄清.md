# 需求澄清

## 背景

- 需求来源：Seedance 视频生成任务返回 Ark `InvalidParameter`，导致分镜视频失败，后续镜头无法使用首尾帧衔接。
- 目标页面或模块：分镜视频生成 Agent、视频生成任务消费链路、火山引擎 Ark 视频策略。

## 输入资料

- 当前请求入口：`GenerateVideoToolExecutor`。
- 当前平台策略：`VolcengineVideoStrategy`。
- 首尾帧生成流程：`storyboard-frame-executor.system.md` 已支持使用参考图调用 `generate_image`，并保存到分镜条目的首帧/尾帧字段。
- 参考工程：`waoowaoo` 的 Ark 生成器将首尾帧模式与多模态参考模式分开构造。

## 目标

- 保证首帧、尾帧能够真正进入 Seedance 视频请求并用于转场连续性。
- 防止 Ark 拒绝首尾帧与参考媒体的非法组合。
- 在请求进入队列或发送外部平台前拦截不符合模型能力的 duration。
- 在需要“参考素材一致性 + 首尾帧控制”时，提供明确、可恢复的两阶段流程。

## 不包含范围

- 不修改 Ark 平台能力，不绕过平台 content 互斥规则。
- 不通过生成一段视频后再叠加首尾帧来补救；后处理无法替代模型生成阶段的首尾帧约束。
- 不在本阶段引入新的数据库字段或视频剪辑服务。

## 业务流程

### 场景一：已有首尾帧

1. 读取分镜条目的 `firstFrameImageUrl` 和可选的 `lastFrameImageUrl`。
2. 直接提交一次 Seedance 视频任务。
3. `content` 仅包含文本、`first_frame` 和可选的 `last_frame`。
4. 不提交 `referenceImageUrls`、`referenceVideoUrls`、`referenceAudioUrls`。
5. 保存视频 URL 和 Ark 返回的尾帧，供下一镜头继续使用。

### 场景二：只有参考图，没有首尾帧

1. 读取角色、道具、场景或画风参考素材。
2. 直接提交一次多模态参考视频任务。
3. 不传 `firstFrameImageUrl` 或 `lastFrameImageUrl`。
4. 在 prompt 中按顺序使用“图片1、图片2”等引用。
5. 此模式不承诺显式首尾帧转场控制。

### 场景三：既需要参考图，又需要显式首尾帧

1. 先调用现有 `generate_storyboard_frame` 流程，使用参考图和帧提示词生成首帧、尾帧关键图。
2. 通过 `update_storyboard_item_frame` 将结果保存到分镜条目的 `firstFrameImageUrl`、`lastFrameImageUrl`。
3. 再调用一次 `generate_video`，只携带已生成的首帧/尾帧，不携带原始参考媒体。
4. 视频成功后保存视频和返回尾帧。
5. 下一镜头可将上一镜头返回的尾帧作为首帧，形成链式连续性。

## 核心口径

- 输入模式：首尾帧模式与参考媒体模式互斥；首尾帧优先级高于参考媒体。
- 尾帧约束：存在尾帧时必须存在首帧；只有尾帧时直接返回业务错误，不把尾帧降级成普通参考图。
- 参考媒体：只在无首尾帧的视频请求中使用；需要同时使用时先转化为关键帧。
- duration：以当前模型能力为准；Seedance 2.0 使用 4-15 秒，默认 5 秒。
- 失败策略：非法组合和非法 duration 在本地返回可读业务错误，不提交外部平台。

## 待确认问题

- 低于模型最小时长的镜头是否允许自动提升并在后续剪辑阶段裁剪。
- 关键帧生成失败时是否允许退化为参考媒体模式；默认建议阻断并提示用户，避免无声丢失转场约束。

## 结论

- “两步”应理解为“参考图 → 首/尾关键帧 → 视频”，而不是“参考图 → 视频 → 再用首尾帧处理视频”。
- 已有首尾帧时只需一步视频生成；只有在关键帧尚未存在且又要求参考素材一致性时才需要先走生图阶段。
