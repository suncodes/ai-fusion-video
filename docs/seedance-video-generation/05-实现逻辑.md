# 实现逻辑

## 实现目标

- 在统一入口确定唯一的视频输入模式。
- 在 Ark 请求前校验帧组合、参考媒体组合和 duration。
- 保持现有分镜首尾帧字段与任务队列结构，不引入数据库迁移。

## Service 流程

1. `GenerateVideoToolExecutor` 解析参数并读取当前模型能力。
2. 若参数中存在 `firstFrameImageUrl` 或 `lastFrameImageUrl`，工具层主动清空 `referenceImageUrls`、`referenceVideoUrls`、`referenceAudioUrls`，避免 Agent 组合出 Ark 必然拒绝的请求。
3. `GenerationModelCapabilityService` 负责统一校验：
   - 只有尾帧没有首帧时直接拒绝；
   - 首帧/尾帧不能与参考图、参考视频、参考音频混用；
   - `duration` 必须为正整数，并满足当前模型的 `minDuration/maxDuration`；
   - 模型不支持的首帧、尾帧或参考媒体继续按原能力规则拒绝。
4. `VideoGenerationConsumer` 在任务执行前复用 `validateVideoTask`，覆盖工具以外的入队路径。
5. `VolcengineVideoStrategy.buildContents` 作为最后一道防线：
   - 首尾帧模式只发送 `text + first_frame + last_frame`；
   - 只有首帧时发送 `text + 普通 image_url`；
   - 无首尾帧时才发送 `reference_image/reference_video/reference_audio`。
6. `GenerationMediaInputResolver` 在 Volcengine 请求出站前把图片类输入转换为 Data URL：
   - `data:image/...;base64,...` 校验后复用；
   - `/media/...` 从本地媒体根目录安全读取；
   - `/art-styles/...` 和 `/api/art-styles/...` 从预设画风资源读取；
   - `http(s)` URL 由服务端下载后转为 Data URL，下载时复用模型代理配置。
7. 成功后沿用现有视频任务流程持久化视频 URL；失败时保存本地业务错误或平台错误。

## 请求模式

### 首尾帧模式

```json
{
  "model": "doubao-seedance-2-0-260128",
  "content": [
    {"type": "text", "text": "描述从首帧到尾帧的动作和运镜"},
    {"type": "image_url", "role": "first_frame", "image_url": {"url": "data:image/png;base64,..."}},
    {"type": "image_url", "role": "last_frame", "image_url": {"url": "data:image/png;base64,..."}}
  ],
  "duration": 5
}
```

### 多模态参考模式

```json
{
  "model": "doubao-seedance-2-0-260128",
  "content": [
    {"type": "text", "text": "参考图片1的角色外观和图片2的场景风格"},
    {"type": "image_url", "role": "reference_image", "image_url": {"url": "data:image/png;base64,..."}},
    {"type": "image_url", "role": "reference_image", "image_url": {"url": "data:image/png;base64,..."}}
  ],
  "duration": 5
}
```

## 代码改动边界

- `GenerationModelCapabilityService`：增加 duration 能力读取、尾帧依赖校验和帧/参考媒体互斥规则；能力快照增加 `minDuration/maxDuration` 和时长摘要。
- `GenerateVideoToolExecutor`：动态展示合法 duration；首尾帧模式不再把参考媒体写入 `VideoTask`；日志标记是否发生参考媒体裁剪。
- `VideoGenerationConsumer`：复用既有统一前置校验，覆盖工具以外的入队任务。
- `GenerationMediaInputResolver`：统一处理图片出站 Data URL 转换，避免模型侧依赖公网 URL。
- `VolcengineImageStrategy`：提交 Ark 图片参考图前转换为 Data URL 列表。
- `VolcengineVideoStrategy`：`buildContents` 按首尾帧、单首帧、多模态参考三种互斥模式构造 Ark content，并把图片类 content 转为 Data URL。
- `storyboard-video-executor.system.md`：明确有首尾帧时不传任何参考媒体，也不在 prompt 中引用不存在的“图片N”。
- `storyboard-frame-executor.system.md`：作为关键帧准备阶段的既有能力继续复用，无需新增接口。

## 两阶段实现时序

```text
参考图/风格/资产
        │
        ▼
generate_storyboard_frame（生首帧/尾帧，允许 imageUrls）
        │
        ▼
update_storyboard_item_frame（保存关键帧）
        │
        ▼
generate_video（只传 first_frame/last_frame）
        │
        ▼
保存 videoUrl + 返回 lastFrameUrl
```

不采用“先生成参考视频，再用首尾帧二次处理”的原因：

- Ark 仍会把参考视频视为 reference media，不能与首尾帧在同一请求中组合。
- 二次视频生成会增加成本和延迟，且无法保证人物、动作和镜头状态保持一致。
- 首尾帧是生成约束，不是生成完成后的简单滤镜，后处理无法补回模型未遵守的起止状态。

## DAO / SQL

- 表：无需新增表或字段。
- 复用字段：`afv_storyboard_item.first_frame_image_url`、`last_frame_image_url`；`afv_video_task` 中的参考媒体和 duration 字段继续保留。
- 持久化：关键帧阶段写回现有分镜字段；视频阶段写回现有视频任务/视频条目字段。

## 外部接口

- Ark 内容生成接口：按输入模式发送互斥的 `content`。
- Ark 查询接口：继续轮询任务状态，并读取返回尾帧作为下一镜头候选首帧。
- 生图接口：仅用于关键帧准备阶段，允许参考图；不把其结果再作为视频参考媒体传入。

## 关键口径与性能点

- 已有首尾帧时跳过生图阶段，避免重复调用。
- 首尾帧可并行准备，但同一镜头必须在两帧都成功后再提交视频。
- 多镜头可并行生成，但跨镜头首尾帧链路必须按镜头顺序传递。
- 不自动重试同一非法 Ark content；修正输入模式后才允许重试。

## 风险与兜底

- 关键帧生成失败：默认阻断视频生成并返回明确错误；不静默退化为参考媒体模式。
- duration 小于模型下限：默认拒绝并提示调整或切换模型；自动提升/裁剪作为后续产品策略。
- 参考媒体被裁剪：日志记录是否发生裁剪，避免误以为素材已参与视频生成。
- 历史任务：消费端按新规则重新校验，旧任务无需迁移数据。
